# API каталога экзопланет

FastAPI читает локальный каталог PostgreSQL. Отдельная команда загружает таблицу `pscomppars` из [NASA Exoplanet Archive TAP](https://exoplanetarchive.ipac.caltech.edu/docs/TAP/usingTAP.html).

## Запуск

Из каталога проекта с установленным Docker Compose:

```sh
docker compose up --build -d
docker compose logs importer
```

После первого успешного импорта откройте [ExoAtlas](http://localhost:8000/), [страницу проверки](http://localhost:8000/check) или [Swagger](http://localhost:8000/docs). Для ручного обновления каталога или запуска из планировщика:

```sh
docker compose run --rm importer
```

Для запуска без Docker установите зависимости из `requirements.txt`, задайте `DATABASE_URL` с адресом своей базы PostgreSQL и выполните:

```sh
python -m catalog.import_catalog
python -m uvicorn catalog.api:app
```

Для публикации с доменом и HTTPS см. [гайд по Timeweb Cloud](TIMEWEB.md).

## Маршруты

| GET | Результат |
| --- | --- |
| `/api/planets` | Список с фильтрами, сортировкой и пагинацией |
| `/api/planets/{planet_id}` | Карточка планеты |
| `/api/stats` | Число планет и группировки по году и методу открытия |
| `/api/systems` | Координаты звёзд для карты и число планет под выбранными фильтрами |
| `/api/systems/{system_id}` | Звезда и все её планеты с параметрами орбит |
| `/api/catalog` | Время последнего успешного импорта и размер каталога |
| `/api/ranking?limit=5` | Первые 5 кандидатов, источник и время пересчёта. Без параметра возвращаются все 50. |

```text
/api/planets?method=Transit&year_from=2020&radius_max=2&sort=radius&page_size=25
/api/stats?method=Transit&year_from=2020&radius_max=2
```

Список, статистика и карта принимают `q` (поиск по имени планеты или звезды), `method`, `year_from`, `year_to`, `radius_min`, `radius_max`, `distance_min`, `distance_max`. Границы включительные. Радиус задаётся в радиусах Земли, расстояние до системы — в парсеках. Планета с неизвестным числовым значением исключается только при фильтрации по этому полю. На карту попадают системы с координатами и положительным расстоянием.

Список дополнительно принимает `page` (от 1), `page_size` (до 100), `sort` (`name`, `year`, `radius`, `distance`) и `order` (`asc`, `desc`).

Импорт проверяет полноту ответа TAP и заменяет каталог одной транзакцией. Читатели видят предыдущий снимок до фиксации нового. UUID определяются именами из архива и сохраняются между импортами, пока имена совпадают. Отсутствующие измерения возвращаются как `null`. Параметры орбит предназначены для визуализации, а их единицы описаны в [документации NASA](https://exoplanetarchive.ipac.caltech.edu/docs/API_PS_columns.html).

## Рейтинг жизнепригодности

Сервис `scheduler` запускает импорт в 00:00 и 12:00 по Москве. Каждый запуск загружает один снимок NASA TAP, считает топ-50 по алгоритму `planet.py` команды и публикует каталог и рейтинг одной транзакцией. Главная берёт первые пять позиций этого рейтинга. До первого успешного пересчёта API отдаёт исходный CSV команды. При ошибке очередного импорта остаётся последний успешный снимок.

Для расчёта используется балльная формула из приложенного скрипта, совпадающая с присланным CSV. Она учитывает радиус, поток, равновесную температуру и бонусы. Раздел 5.8 PDF также описывает вариант 70% ESI + 30% HZ. Этот вариант в приложенном скрипте отсутствует.
